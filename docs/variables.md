# Variables

Generated by `just docs` from the comments in the files named below; do not edit it. To change a default, edit the file it comes from and run `just docs`.

Each table row names the file the setting is defined in. Where a value comes from, lowest priority first: a role's `defaults/main.yml`, `group_vars/all/defaults.yml`, `group_vars/all/vars.yml` (yours), `host_vars/<host>/vars.yml` (yours, one host). A later one wins. Image versions are in `group_vars/all/versions.yml`; `group_vars/all/derived.yml` holds computed values and is not edited.

Examples to start from: `group_vars/all/vars.yml.example` (the settings with no default), `host_vars/vars.yml.example` (one host), and the two `vault.yml.example` files (secrets).

### Backups (docs/backups.md)

The backup role runs on a host with `backup_local_enabled` or `backup_cloud_enabled` set to true. Local needs a drive with the `backup` role; cloud needs `restic_cloud_repository`. Without local backup, logs and service dumps live in /var/lib/backup-work on the root drive.

| Setting | Default | What it does | Defined in |
|---|---|---|---|
| `service_dump_scripts_dir` | `"{{ scripts_dir }}/dump.d"` | One dump script per service with a live database. | `group_vars/all/defaults.yml` |
| `restic_repo_path` | `"{{ backup_drive }}/restic-repo"` | Local repository; used only when a backup drive is claimed. | `group_vars/all/defaults.yml` |
| `restic_cloud_repository` | `""` | Offsite repository. The URL scheme picks the backend (docs/backups.md#offsite-repository-restic_cloud_repository): "rclone:gdrive-nas:/path" for Google Drive, "sftp:user@host:/path" for SFTP. The deploy fails if it cannot be initialised. Set it per host in host_vars (each host needs its own path: hosts sharing a repository would prune each other's snapshots). | `group_vars/all/defaults.yml` |
| `restic_password_file` | `"/home/{{ ansible_user }}/.restic-password"` | File holding the restic repository password, written from vault_restic_password. | `group_vars/all/defaults.yml` |
| `backup_logs_dir` | `"{{ backup_work_dir }}/logs"` | Where the backup logs are written. | `group_vars/all/defaults.yml` |
| `service_dumps_dir` | `"{{ backup_work_dir }}/service-dumps"` | Where the dump.d scripts write database dumps before each backup; the local backup includes this directory. | `group_vars/all/defaults.yml` |
| `restic_local_rules` | `(long; see the file)` | What the local (daily) backup copies and skips, one rule per line: Example: The service dumps dir is always added, and caches and live database directories are always skipped (roles/backup/templates/restic-excludes-*.txt.j2); your "- " lines come after those, so "- !" can undo a default. Default: the primary and fast drives; a host with neither role backs up the user's home. The backup runs as the ansible user, so files only root can read (/etc, container-owned data) are skipped: restic reports "unreadable source files" in the log and the run still counts as done. CAUTION: restic groups snapshots by host + paths, so adding or removing a path line starts a new snapshot group; the old group's last snapshots stay until you run `restic forget --path <old path> ...` by hand (docs/plans/drive-migration.md). Changing "- " lines never splits a group. | `group_vars/all/defaults.yml` |
| `restic_cloud_rules` | `(long; see the file)` | The same rules for the weekly offsite backup. Each path is its own snapshot group, and a "- " line applies to every path. Default: this host's base directory (compose files, credentials), Copyparty's config, and, when the host has no local backup, the local rules above, so the offsite copy holds its data. Add more paths to upload more; Immich's photos are not included (they are large): add "{{ immich_upload_location }}". | `group_vars/all/defaults.yml` |
| `restic_local_retention` | `"--keep-daily 7 --keep-weekly 4 --keep-monthly 1"` | restic forget options for the local repository: snapshots kept per day, week and month. | `group_vars/all/defaults.yml` |
| `restic_cloud_retention` | `"--keep-weekly 12 --keep-monthly 6"` | restic forget options for the offsite repository: snapshots kept per week and month. | `group_vars/all/defaults.yml` |
| `restic_cloud_rclone_args` | `"serve restic --stdio --tpslimit=10"` | rclone's default Google Drive client is shared by all rclone users, so a burst of small uploads can fail with 403 RATE_LIMIT_EXCEEDED. This throttle avoids that; no custom OAuth client (docs/backups.md). | `group_vars/all/defaults.yml` |
| `restic_command_timeout` | `"2h"` | Every restic call in the backup scripts is wrapped in `timeout` with this value, so a stalled rclone or network pipe cannot hold the repo lock indefinitely. | `group_vars/all/defaults.yml` |
| `restic_cache_dir` | `(long; see the file)` | restic's index and snapshot cache. On the fast drive it keeps cache reads off the backup drive and off Google Drive; it only helps once the fast and backup roles are different drives. Not backed up. A host without a fast drive keeps it in the user's ~/.cache. | `group_vars/all/defaults.yml` |

Example for `restic_local_rules`:

```yaml
  /path        back this path up (an absolute path)
  - pattern    leave this out (the "- " is a dash and a space; restic exclude syntax, `**` matches any depth)
  - !pattern   put back something an earlier "- " line left out
  restic_local_rules:
    - /mnt/data                                  # back up this drive
    - /home/pi/notes                             # and this folder
    - "- **/*.iso"                               # but no .iso file
    - "- !/mnt/data/downloads/keep.iso"          # except this one
```

### Data directories (teardown.yml also reads them)

One variable per service. To move a service to another drive, set its variable in host_vars/&lt;host&gt;/vars.yml (procedure: docs/storage.md#move-one-services-data). Keep the new path under a drive that has a role, or the default backup (restic_local_rules) does not cover it. A variable that uses a drive role fails with a message naming the role if no entry in `drives` claims it, but only on a host that enables the service. Random-IO data (databases, configs) is on the fast drive; bulk data (photos, files) is on the primary. When both roles are the same drive, the split changes nothing on disk.

### Copyparty

Every service that publishes a host port is reachable at http://&lt;host-tailscale-name&gt;:&lt;port&gt; from any device on your tailnet. That needs nothing extra: no `tailscale serve`, no funnel. The funnel (roles/tailscale_funnel/defaults/main.yml) only gives Copyparty a public ts.net name; pics' guest pages go through the Cloudflare tunnel (a cloudflared_ingress entry that points at pics_public_port).

| Setting | Default | What it does | Defined in |
|---|---|---|---|
| `copyparty_user` | `"{{ vault_copyparty_user }}"` | The Copyparty admin login, from the vault. | `group_vars/all/defaults.yml` |
| `copyparty_pass` | `"{{ vault_copyparty_pass }}"` | The Copyparty admin password, from the vault. | `group_vars/all/defaults.yml` |
| `copyparty_collab_dir` | `"{{ primary_drive }}/collab"` | shared directory for friends | `group_vars/all/defaults.yml` |
| `copyparty_port` | `3923` | Host port of Copyparty's web UI and WebDAV. | `group_vars/all/defaults.yml` |
| `copyparty_service_accounts` | `[]` | Accounts for apps that talk to Copyparty. Each gets its own volume at /&lt;folder&gt;, stored in copyparty_files_dir/&lt;folder&gt;; the admin gets A on it too. Two entries can't share a folder. Passwords go in the vault. Example, a photo app: no d on photos, so without delete Copyparty also refuses overwrites (it renames instead) and the app can't destroy a photo; it may delete only in its own photos-trash volume. | `group_vars/all/defaults.yml` |

Example for `copyparty_service_accounts`:

```yaml
  - user: photos
    pass: "{{ vault_copyparty_photos_pass }}"
    volumes:
      - { folder: photos, perms: rwm }
      - { folder: photos-trash, perms: rwmd }
```

### pics

Builds from a private repo with vault_github_read_token. It reaches Copyparty as the "photos" account above. The container publishes &lt;pics_port&gt; on the Pi, so the whole app (owner pages included) is on your LAN and tailnet with no `tailscale serve` needed. Only guest pages go public, through the cloudflared_ingress entry, which points at pics_public_port.
